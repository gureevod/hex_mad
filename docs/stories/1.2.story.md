# Story 1.2: Owner Configuration and Google Guice DI Pattern

## Status
Approved

## Story
**As a** test developer,
**I want** Owner-backed configuration and Google Guice dependency injection,
**so that** test-time wiring is clear and type-safe with minimal configuration overhead.

## Acceptance Criteria
1. Owner interfaces support environment profiles (local, CI) and immutable per-thread snapshots.
2. Google Guice modules documented with proper binding configuration; no static mutable singletons.
3. Example wiring for API client and UI driver/session via Guice injection.
4. Unit tests verify configuration snapshot immutability and per-thread scoping.

### Configuration Model Details
[Source: architecture/data-models.md#Framework Configuration Model]
- Configuration interfaces must be Java interfaces using the Owner library
- Use annotations: `@Config.Sources`, `@Key`, `@DefaultValue` for property loading
- Profiles will manage different environments (e.g., `local`, `ci`)
- A central `ConfigFactory` will provide thread-safe, immutable instances
- Configuration interfaces can be composed by extending multiple parent interfaces

Example ApiConfig attributes to implement:
- `baseUrl()`: String - The base URL for the API under test
- `port()`: int - The port number for the API service  
- `readTimeout()`: int - The timeout in milliseconds for reading a response
- `logRequests()`: boolean - A flag to enable or disable request logging

### Google Guice DI Pattern
[Source: architecture/high-level-architecture.md#Architectural and Design Patterns]
- Use Google Guice 7.0.0 for lightweight dependency injection
- Provides compile-time safe dependency injection with minimal configuration overhead
- Must promote test-time flexibility and explicit, thread-safe dependency management
- Per-thread context creation including immutable configuration snapshot via DI providers

[Source: architecture/high-level-architecture.md#High Level Overview]
Data flow for test initialization:
1. JUnit 5 test class is instantiated
2. Per-thread context created with immutable config snapshot (via Owner) and service/driver instances (via DI providers)
3. Test interacts with API service classes or UI PageObjects

### File Locations

Configuration and DI code locations:
- `hex-core/src/main/java/com/company/hex/core/config/` - Core Owner interfaces, ConfigFactory
- `hex-core/src/main/java/com/company/hex/core/di/` - Google Guice modules and provider interfaces
- Sample implementations in `hex-project-samples/src/main/java/com/company/hex/project/config/`

### Coding Standards
[Source: architecture/coding-standards.md]
- All public classes and methods must have Javadoc in Russian (NFR11)
- No use of `new` to instantiate services, drivers, or PageObjects within tests - must use Guice injection
- Prefer immutable objects, especially for configuration objects
- Use `final` fields where possible
- No static mutable singletons allowed
- Package naming: lowercase, dot-separated (e.g., `com.company.hex.core.config`)
- Class naming: PascalCase (e.g., `ConfigFactory`, `ApiConfig`)

### Testing Requirements
[Source: architecture/testing-strategy.md]
- Minimum 85% line coverage required for hex-core modules
- Use JUnit 5 (5.10.2) with Mockito (5.12.0) for unit tests
- Follow AAA pattern (Arrange, Act, Assert)
- Test both happy paths and exceptional cases
- Mock all external dependencies
- File convention: `*Test.java` (e.g., `ConfigFactoryTest.java`)
- Location: `hex-core/src/test/java/com/company/hex/core/config/` and `hex-core/src/test/java/com/company/hex/core/di/`

### Error Handling
[Source: architecture/error-handling-strategy.md]
- Create `HexConfigException` extending `HexFrameworkException` for configuration-related errors
- Use SLF4J logging for all configuration loading and DI operations
- Include correlation ID via MDC (Mapped Diagnostic Context) for test run correlation

### Thread Safety Requirements
[Source: architecture/high-level-architecture.md]
- Configuration objects provided by Owner must be treated as immutable snapshots for each thread
- Critical for achieving thread-safety and preventing state corruption during parallel test execution
- No global state or static mutable singletons allowed

### Testing
Testing Standards from Architecture:
- Test file location: `src/test/java` within hex-core module
- Test standards: JUnit 5 with Mockito for mocking
- Testing frameworks: JUnit 5 (5.10.2), Mockito (5.12.0)
- Specific testing requirements: 85% code coverage, AAA pattern, test immutability and thread-safety
