# Story 2.4: Declarative API Framework Improvements

## Status
Draft

## Story
**As an** API test developer,
**I want** improved performance, flexibility, and error handling in the declarative API framework,
**so that** I can write more reliable tests with better diagnostics and configuration options.

## Acceptance Criteria

### AC1: Annotation Metadata Caching
1. `AnnotationProcessor` caches parsed method metadata using `ConcurrentHashMap`
2. Subsequent calls to the same method reuse cached metadata
3. Performance improvement measurable in tests (≥50% reduction in reflection overhead)

### AC2: @Headers Annotation Support
1. New `@Headers` annotation available for method-level header definitions
2. Multiple headers can be defined: `@Headers({"Content-Type: application/json", "X-Custom: value"})`
3. Method-level headers merge with parameter-level `@Header` annotations
4. Sample tests demonstrate the feature

### AC3: ApiServiceFactory Builder Pattern
1. `ApiServiceFactory.builder()` returns a fluent builder
2. Builder supports: `addInterceptor()`, `withConfig()`, `withConverter()`, `withExecutor()`
3. Interceptor ordering is configurable via `addInterceptorFirst()`, `addInterceptorAfter()`
4. Static `create()` methods remain for backward compatibility

### AC4: Improved Property Placeholder Resolution
1. `AnnotationProcessor` resolves `${property}` placeholders from multiple sources
2. Resolution order: System properties → HexConfigFactory → Environment variables → default value
3. Supports default values: `${api.url:http://localhost:8080}`

### AC5: Eager Annotation Validation
1. `ApiServiceFactory.create()` validates all interface methods upfront
2. Missing HTTP method annotations throw `HexConfigException` immediately
3. Invalid annotation combinations are detected at proxy creation time
4. Clear error messages indicate the problematic method and annotation

### AC6: Enhanced Error Handling
1. New `ApiResponseException` class with detailed diagnostic information
2. Exception includes: HTTP status, response body, expected type, request details
3. `JacksonResponseConverter` throws `ApiResponseException` instead of generic `RuntimeException`
4. Error messages guide developers to fix DTO mapping issues

### Code Examples

#### Using the New Builder
```java
// Custom interceptor for authentication
public class AuthInterceptor implements Interceptor {
    private final String token;
    
    public AuthInterceptor(String token) {
        this.token = token;
    }
    
    @Override
    public Response intercept(Chain chain) {
        RequestDefinition request = chain.request();
        request.getHeaders().put("Authorization", "Bearer " + token);
        return chain.proceed(request);
    }
}

// Usage
UserApi userApi = ApiServiceFactory.builder()
    .withConfig(customConfig)
    .addInterceptorFirst(new AuthInterceptor(getToken()))
    .addInterceptor(new MetricsInterceptor())
    .create(UserApi.class);
```

#### Using @Headers Annotation
```java
@ApiService(baseUrl = "https://api.example.com")
public interface PaymentApi {
    
    @POST("/payments")
    @Headers({
        "Content-Type: application/json",
        "X-API-Version: 2",
        "X-Idempotency-Key: ${idempotency.prefix}-{timestamp}"
    })
    PaymentResult processPayment(@Body PaymentRequest request);
}
```
