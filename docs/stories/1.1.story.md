# Story 1.1: Bootstrap `hex-core` Modules and Project Structure

## Status
Draft

## Story
**As a** framework maintainer,
**I want** a multi-module Maven structure with `hex-core-api`, `hex-core-ui`, and `hex-core-testing`,
**so that** teams can import focused modules and avoid unrelated dependencies.

## Acceptance Criteria
1. A Maven parent POM defines modules `hex-core-api`, `hex-core-ui`, `hex-core-testing`, and a sample `hex-project-samples`.
2. Shared dependency management with pinned versions for Java 17, RestAssured, Selenide, JUnit 5, Allure, Owner, SLF4J/Logback, Lombok, JavaFaker.
3. Each module builds successfully locally and in CI.
4. Sample project depends on `hex-core-*` without test flakiness in a single-thread run.
5. All module READMEs and Javadocs are created in Russian.

### Project Structure Requirements
[Source: architecture/source-tree.md]
The framework must follow the exact Maven multi-module structure defined in the architecture:

```
hex-automation-framework/
├── hex-core-api/
│   ├── src/main/java/com/company/hex/api/
│   │   ├── config/         # Owner interfaces for API config
│   │   ├── dto/            # Base DTO interfaces/classes  
│   │   └── service/        # BaseApiService and helpers
│   └── pom.xml
├── hex-core-ui/
│   ├── src/main/java/com/company/hex/ui/
│   │   ├── config/         # Owner interfaces for UI config
│   │   ├── core/           # BaseElement, BaseComponent
│   │   └── wrappers/       # Button, Input, Select, etc.
│   └── pom.xml
├── hex-core-testing/
│   ├── src/main/java/com/company/hex/testing/
│   │   ├── allure/         # Allure integration helpers
│   │   ├── config/         # ConfigFactory
│   │   ├── di/             # DI Providers/Factories
│   │   ├── lifecycle/      # BaseTest, JUnit extensions
│   │   └── logging/        # Logging configuration helpers
│   └── pom.xml
├── hex-project-samples/
│   ├── src/main/java/com/company/hex/project/
│   └── pom.xml
└── pom.xml                 # Parent POM
```

### Architectural Patterns to Implement
[Source: architecture/high-level-architecture.md]
- **Modular Monorepo**: Maven parent POM managing shared dependencies and build lifecycle
- **Dependency Injection**: Provider/Factory pattern for thread-safe dependency management
- **No Global Singletons**: All dependencies supplied via DI providers

### Coding Standards Requirements
[Source: architecture/coding-standards.md]
- **Java 17 Compatibility**: All code must be compatible with Java 17
- **Google Java Style Guide**: Checkstyle configuration must be integrated
- **Package Naming**: lowercase, dot-separated (e.g., `com.company.hex.api.config`)
- **Class Naming**: PascalCase (e.g., `BaseApiService`, `UiConfig`)
- **Russian Documentation**: All Javadocs must be in Russian per NFR11

### File Locations
- Parent POM: `pom.xml` (project root)
- Module POMs: `{module-name}/pom.xml`
- Java source: `{module-name}/src/main/java/com/company/hex/{domain}/`
- Test source: `{module-name}/src/test/java/`
- Module READMEs: `{module-name}/README.md`

### Technical Constraints
- **Build Tool**: Apache Maven 3.9.6 minimum
- **Java Version**: Java 17 LTS (compilation target and runtime)
- **Thread Safety**: All components must be thread-safe for parallel execution
- **No External Infrastructure**: Framework builds and tests must run without external dependencies

### Testing
[Source: architecture/test-strategy-and-standards.md]

**Test Organization:**
- Test files location: `src/test/java` within each core module
- Test file naming: `*Test.java` suffix (e.g., `ModuleStructureTest.java`)
- Framework: JUnit 5 with Mockito for mocking
- Coverage requirement: 85% line coverage enforced by JaCoCo

**Test Standards:**
- Follow AAA pattern (Arrange, Act, Assert)
- Mock all external dependencies using Mockito (5.12.0)
- Generate tests for all public methods
- Cover both happy paths and exceptional cases
- Use `@Tag("integration")` for integration tests

**Unit Test Requirements for this Story:**
- Test Maven module structure validation
- Test dependency resolution and classpath isolation
- Test that each module compiles independently
- Test that sample project can import all core modules
- Verify no circular dependencies exist
