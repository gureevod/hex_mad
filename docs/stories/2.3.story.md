# Story 2.3: Hybrid Imperative and Declarative API Implementation

## Status
Approved

## Story
**As an** API test developer,
**I want** to have the option to use both declarative and imperative approaches for API testing,
**so that** I can handle complex scenarios that are not easily covered by annotations while leveraging the simplicity of the declarative style for standard cases.

## Acceptance Criteria
1.  A `BaseApiService` class is available that provides direct access to a pre-configured RestAssured `RequestSpecification`.
2.  Developers can create hybrid services that combine declarative methods (using annotations) with imperative methods (using raw RestAssured).
3.  The framework supports an "escape hatch" allowing developers to get a configured `RequestSpecification` or `RequestExecutor` instance from the `ApiServiceFactory`.
4.  A sample `UserApiHybridService` is created in `hex-project-samples` to demonstrate the combination of both approaches.
5.  Imperative methods seamlessly integrate with the framework's existing logging, reporting, and configuration.
6.  Documentation is updated to provide clear guidelines on when to choose a declarative, imperative, or hybrid approach.

## Tasks / Subtasks
- [ ] Task 1: Enhance `BaseApiService` for Imperative Usage
    - [ ] Subtask 1.1: Expose a protected `getRequestSpecification()` method in `BaseApiService`.
- [ ] Task 2: Update `ApiServiceFactory` to Support Hybrid Services
    - [ ] Subtask 2.1: Add a method to the factory to retrieve a pre-configured `RequestExecutor` or `RequestSpecification`.

## Dev Notes

### Rationale
While the declarative approach covers 80% of use cases, there will always be scenarios that require the full power and flexibility of raw RestAssured. This story provides a structured way to handle those exceptions without abandoning the benefits of the Hex framework.

The goal is not to replace the declarative model, but to complement it, offering a clear and supported path for handling complexity. This "escape hatch" ensures the framework is never a bottleneck.
