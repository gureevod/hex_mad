# Лучшие практики и Антипаттерны

Чтобы ваши API тесты оставались чистыми, поддерживаемыми и быстрыми, следуйте этим рекомендациям.

## Паттерны (Как делать правильно)

### 1. Один интерфейс на один ресурс
Группируйте методы по доменным областям. Не создавайте один гигантский `Api.java` для всего приложения.

*   ✅ `UserApi.java`, `OrderApi.java`, `ProductApi.java`
*   ❌ `MyApplicationApi.java`

### 2. Используйте DTO
Всегда создавайте POJO классы для запросов и ответов. Это обеспечивает типобезопасность и упрощает рефакторинг.

*   ✅ `UserDto createUser(@Body CreateUserRequest request);`
*   ❌ `Map<String, Object> createUser(@Body Map<String, Object> request);`

### 3. Явные ожидания
Используйте `@ExpectedStatus` для декларативной проверки успешности операции. Это делает тесты чище, убирая необходимость писать `assertThat(response.getStatusCode()).isEqualTo(200)`.

### 4. Наследование конфигурации
Используйте базовый интерфейс для общих настроек, если у вас микросервисная архитектура с разными базовыми URL.

```java
@ApiService(baseUrl = "${service.users.url}")
public interface UserApi extends BaseApi { ... }
```

## Антипаттерны (Как делать не надо)

### 1. Логика в интерфейсах
Интерфейсы API должны содержать только объявления методов. Не добавляйте туда `default` методы со сложной бизнес-логикой или проверками.

### 2. Смешивание UI и API
Не вызывайте API методы напрямую из Page Object классов. Используйте API шаги (Steps) или сервисы как отдельные компоненты в тесте.

### 3. Хардкод URL
Не пишите полные URL в аннотациях методов. Используйте `baseUrl` в `@ApiService` и относительные пути в методах.

*   ✅ `@ApiService(baseUrl = "...")` + `@GET("/users")`
*   ❌ `@GET("https://api.example.com/v1/users")`

### 4. Игнорирование ошибок
Не используйте `void` для методов, которые возвращают важные данные, просто чтобы "заглушить" ошибку десериализации. Лучше исправьте DTO.

## Советы по миграции

Если вы переходите с императивного RestAssured:

1.  Начните с новых эндпоинтов. Пишите их сразу в декларативном стиле.
2.  Выделите часто используемые вызовы RestAssured в интерфейсы.
3.  Используйте `ApiServiceFactory.getRequestSpecification()` как временное решение для сложного легаси кода, который трудно переписать сразу.
